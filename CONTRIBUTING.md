# Contributing to Lawn With Care Universe

## Purpose

This document defines how humans and AI collaborators should contribute to the Lawn With Care Universe repository.

The repository is the official source of truth for the franchise.

Contributions must preserve canon, consistency and traceability.

## Before Editing

Read:

1. `PROJECT_CONTEXT.md`
2. `CANON.md`
3. `AI_CONTEXT.md`
4. the authoritative documents related to the area being changed

Do not edit canon based only on memory or conversation history.

## Contribution Principles

- Preserve existing canon.
- Avoid duplicated definitions.
- Edit the authoritative source instead of copying rules into unrelated files.
- Distinguish proposals from approved canon.
- Keep terminology consistent.
- Prefer clarity over complexity.
- Document meaningful changes.

## Canon Changes

A change affecting established canon must:

1. identify the current rule;
2. explain the proposed change;
3. update the authoritative document;
4. update dependent documents when necessary;
5. record the change in `CHANGELOG.md`.

Do not silently overwrite canon.

## New Ideas

New ideas should initially be marked as one of:

- DRAFT
- PROPOSAL
- EXPERIMENTAL
- NON-CANON

Only approved concepts should receive CANON status.

## Character Changes

Before changing a character, review:

- Identity
- Visual DNA
- Canon
- Design Rules
- Prompt Master

Do not modify appearance, personality or recurring behavior in isolation.

## Story Contributions

Before writing or editing an episode, review:

- Story Bible
- Episode Structure
- Dialogue
- Humor
- Educational Framework
- Pacing
- Discovery Moments
- relevant character canon

## Scientific Content

Scientific claims must be accurate enough for the target audience.

Simplification is allowed.

Fabrication is not.

If uncertainty remains, state the uncertainty rather than inventing certainty.

## Visual Contributions

Visual work must respect:

- official palette
- character model consistency
- visual DNA
- design rules
- official assets
- Discovery Frame rules

## File Naming

Follow the existing repository naming conventions.

Do not rename canonical files casually.

Update internal references when renaming is necessary.

## Commit Style

Prefer focused commits.

Examples:

`Expand Brooks visual canon`

`Add Episode 001 blueprint`

`Refine Discovery Badge rules`

`Add Instagram carousel production format`

Avoid vague commit messages such as:

`updates`

`changes`

`fix stuff`

## Versioning

Tags represent historical milestones and should not be rewritten.

Current foundation tag:

`v0.1.0-foundation`

Future work should build forward from that milestone.

## Final Rule

When uncertain, protect consistency first.

Ask before redefining canon.
