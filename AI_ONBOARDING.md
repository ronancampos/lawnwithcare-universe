# AI Onboarding

## Purpose

This is the reading path for any new human or AI collaborator before doing substantive work in this repository.

`CLAUDE.md`, `GEMINI.md` and `COPILOT.md` each list a short required-reading set for their respective tools; this document is the shared, detailed version behind those lists. If those files and this one ever disagree on order, follow this one and flag the discrepancy.

Note: this file previously contained project-status content (percentages, canon completion, priorities) mislabeled under the "AI Onboarding" filename. That content was moved to `PROJECT_STATUS.md`, its correct home, on 2026-08-10 — see `CHANGELOG.md`.

---

## Read in this order

1. **`PROJECT_CONTEXT.md`** — what this repository is, the core franchise idea, the authority hierarchy, the working rules (don't invent canon, flag gaps explicitly).

2. **`CANON.md`** — index of every canonical source in the repository, organized by authority level. Use it to find the right document instead of guessing a path.

3. **`AGENTS.md`** — how AI and coding agents must operate here: canon-change policy, document-status system, git safety, what requires the owner's explicit approval versus what's safe to do autonomously.

4. **`PROJECT_STATUS.md`** — what exists today, what's actively in progress, what's deliberately deferred. Read this so you don't propose work that's already done, already planned, or explicitly postponed.

5. **Then, only what the task actually needs:**

   - **Character work** → the character's `00-Identity.md` and `14-Canon.md` under `01-Characters/<Character>/`, plus `Relationship-Canon.md` if two characters interact in the scene.
   - **Story work** → `Storytelling-DNA.md` (emotional structure) and `03-Storytelling/00-Story-Bible.md`.
   - **Visual work** → the character's Master Model Sheet, Design Rules, Wardrobe and Visual Canon Audit (if one exists), plus `00-Franchise/Art-Direction.md`.
   - **Episode work** → the episode's own numbered pipeline in order: Concept → Learning Objective → Story Blueprint → Script → Panel Breakdown → Visual Prompts → Production Checklist.

## Ground Rules

Full detail lives in `AGENTS.md`; the load-bearing ones:

- The repository is the source of truth — not conversation memory, not model knowledge.
- Never silently invent canon. If something isn't defined, say so and propose an option; don't assume a plausible answer is the approved one.
- A document's status label (`DRAFT`, `CANDIDATE`, `LOCK`, `CANON`, etc.) governs how much authority it carries. A complete-looking draft is still a draft.
- Canon changes — character identity, visual identity, relationships, world rules, terminology — require the project owner's explicit approval. Expansion (adding non-contradictory detail) may proceed with more latitude; change never does.
- If two sources at the same authority level conflict, stop and report it. Don't silently pick one.
